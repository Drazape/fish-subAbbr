# Erase
| Trigger | Event |
| :-----: | :---: |
| After erasing an abbr | `awabbre_erase` |

## Tokens
When the event is emitted, all the identifiers passed by the user (to the [*Erase* sub-command][erase-subcommand]{data-preview} of `awabbre`) are passed as is to the hook function.

[erase-subcommand]: ../../../Arguments/Sub-Commands/Erase.md

## Example uses
Validating requests
:   The user might erase an abbreviation that another abbreviation depends on.  
    In this case, the package should warn the user about the potential consequences of erasing the abbreviation, and ask if the user wants to re-add it, or also remove the dependent abbreviation. The user should be able to bypass this prompt.  
    Such a warning shouldn't be brought up in non-interactive mode.

Suggesting a fixed version
:   When the user erases an abbreviation, the hook can scan for a known typical error, search for similar abbreviation in repositories, and also suggest a fixed version of the abbreviation to the user.  

:   The hook should display a message to the user with the possible mistake, prompt the user to add a similar abbreviation from the repositories, or to add an automatically fixed version.

Logging the event for other uses
:   The event can be logged for various purposes—like debugging, statistics, and reporting

Garbage collection
:   There could be leftover data (runtime or static) related to the erased abbreviation that might be generated by another wrapper, hook, or expander. The hook can be used to clean up such data.
